CWE-639

01 / THE WEAKNESS

AUTHORIZATION
IDOR occurs when an application accepts an object identifier but fails to check whether the current user may access that specific object. Changing a record ID should never grant access by itself.
CWE 639OWASP A01:2021 Broken Access Control*OBJECT-LEVEL AUTHORIZATION

04 / SECURITY FIX

OWNER-SCOPED LOOKUP
01async function getRecord(req, db) {02 const user = req.authenticatedUser;03 if (!user) throw new Error('Unauthorized');04 const recordId = req.params.recordId;05 const record = await db.records.findOne({06 id: recordId, ownerId: user.id07 }); // ID and authenticated owner08 if (!record) throw new Error('Not found');09 return record;10}
Lines 05–07: scope the query to the authenticated owner; the same changed ID now returns no record.

IMPACT / WHY IT MATTERS

A real IDOR can expose or let someone alter another person's private records. This fictional lab demonstrates read access only. Enforce authorization on every object operation; complex IDs are not a substitute for access checks.

FIELD NOTES

The owner identity comes from trusted authentication context—not from a value the requester can change.
