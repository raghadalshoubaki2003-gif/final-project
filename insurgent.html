01 / THE WEAKNESS

CONCURRENCY
A race condition happens when concurrent operations access shared state without adequate synchronization. If each request checks availability before either updates it, both may act on stale state.

04 / SECURITY FIX

ATOMIC CONDITIONAL UPDATE
01async function claim(resource, request) {02 const result = await db.updateWhere({03 id: resource.id, available: true04 }, { available: false, claimant: request.id });05 if (result.changedRows === 1) return 'claimed';06 return 'unavailable';07}
Lines 02–05: a single conditional write allows one winner; production systems need database-supported atomicity.

IMPACT / WHY IT MATTERS

In real systems, timing bugs may produce double claims, duplicate redemptions, or inconsistent state. The browser demo staggers two fictional async tasks; it is illustrative, not a real multi-threaded or database race.

FIELD NOTES

A JavaScript demo can illustrate interleaving with async tasks. Production correctness must rely on atomic database operations, transactions, locks, or another appropriate synchronization strategy.
